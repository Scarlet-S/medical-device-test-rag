# PRACTICE005｜安装、升级、回滚与兼容性测试

> 文档性质：项目原创工程实践，不是监管要求。软件发布、部署和更新的正式要求应检索 DOC001、DOC003 和 DOC004。

## 目标

验证软件在受支持环境中的安装、配置、升级、回滚和卸载过程可控，版本、数据、配置和依赖关系保持一致。

## 测试矩阵

- 全新安装与覆盖安装。
- 从每个受支持旧版本升级到目标版本。
- 跨多个版本升级。
- 升级失败后的恢复或回滚。
- 数据库结构迁移与历史数据兼容。
- 操作系统、硬件、浏览器、数据库和外设组合。
- 在线、离线、受限网络和代理环境。

## 安装测试

1. 检查安装包完整性、版本标识和依赖检测。
2. 验证默认路径、自定义路径、磁盘空间不足和权限不足。
3. 检查安装中断、重复安装和并发安装。
4. 验证初始配置、服务启动、端口、证书和日志。
5. 检查卸载后数据保留与清理是否符合设计。

## 升级与回滚测试

- 升级前备份和兼容性检查。
- 配置、用户、权限、审计日志和历史数据迁移。
- 升级过程中的服务可用性和用户提示。
- 失败点注入：下载、解压、校验、数据库迁移、服务重启。
- 回滚触发条件、回滚步骤和回滚后的版本一致性。
- 不支持降级时的阻止机制和明确提示。

## 兼容性测试

根据实际支持声明组合环境，不追求无边界枚举。优先覆盖：

- 市场占有率高的受支持环境。
- 高风险硬件和外部接口。
- 近期变更影响的依赖版本。
- 历史故障较多的组合。
- 最低配置和最高负载环境。

## 建议证据

- 安装与升级矩阵。
- 安装包哈希和版本清单。
- 数据迁移前后校验报告。
- 失败注入、回滚和恢复日志。
- 兼容性差异与不支持环境清单。

## 退出标准示例

- 所有声明支持的升级路径通过验证。
- 升级失败不会造成不可恢复的数据或配置损坏。
- 版本、数据库结构、配置和依赖保持一致。
- 回滚限制和用户操作要求已明确验证。
