# 小规模 GraphRAG 对照实验 v1

## 实验目的

验证实体关系路径扩展能否补齐普通文本检索容易遗漏的中间证据。该实验是离线、确定性、零模型调用的 GraphRAG-style 检索对照，不替代 RAGFlow 在线检索，也不宣称已经实现生产级 Microsoft GraphRAG 全套流程。

## 实验设计

- 语料：20 个医疗器械软件质量控制知识片段。
- 图谱：19 个实体、18 条带证据片段的关系。
- 题集：6 道多跳题和 2 道单跳对照题。
- 普通基线：中文 2—4 字符 n-gram 与英文词元的加权文本检索。
- GraphRAG：从问题中的起止实体寻找最短关系路径，再以关系对应的原始片段补全候选证据。
- 公平设置：两种方法均返回 Top-4；GraphRAG 没有增加返回条数。
- 指标：预期证据片段 Recall@4、完整证据链命中率。

实验题、实体、关系和证据片段冻结在 `evaluation/graphrag/medical_device_graph_v1.json`。

## 结果

| 题型 | 指标 | 普通文本检索 | GraphRAG | 变化 |
|---|---|---:|---:|---:|
| 多跳（6题） | 平均证据 Recall@4 | 72.2% | 100.0% | +27.8 个百分点 |
| 多跳（6题） | 完整证据链命中率 | 33.3% | 100.0% | +66.7 个百分点 |
| 单跳（2题） | 平均证据 Recall@4 | 100.0% | 100.0% | 持平 |

逐题结果：

| 题目 | 多跳链路 | 普通检索 | GraphRAG | 结论 |
|---|---|---:|---:|---|
| G001 | 软件危险 → 风险控制 → 安全需求 → 设计代码 → 测试证据 | 50.0% | 100.0% | 改善 |
| G002 | 软件更新 → 回归范围 → 回归结果 → 缺陷记录 | 100.0% | 100.0% | 原本已完整 |
| G003 | 威胁建模 → 安全控制 → 安全测试 → 剩余漏洞 | 100.0% | 100.0% | 原本已完整 |
| G004 | 现成软件变化 → 影响分析 → 回归范围 → 回归结果 | 66.7% | 100.0% | 改善 |
| G005 | 用户角色 → 审计日志 → 网络安全测试 | 50.0% | 100.0% | 改善 |
| G006 | 缺陷记录 → 风险分析 → 回归范围 → 回归结果 | 66.7% | 100.0% | 改善 |

结果表明，图关系扩展主要改善了“问题只表达起点和终点、答案需要补齐中间过程”的问题。对于问题文本已经直接覆盖所有证据关键词的 G002、G003，以及单跳题，图检索没有额外收益。

## 运行方式

```powershell
python scripts/run_graphrag_comparison.py `
  --output-json evaluation/results/graphrag_local.json `
  --output-csv evaluation/results/graphrag_local.csv `
  --fail-on-no-multihop-improvement
```

该命令不访问 RAGFlow、Embedding、Rerank 或 LLM API，不消耗模型额度。GitHub Actions 会在每次提交和 Pull Request 中重复运行相同实验，若多跳题不再产生改善则使 CI 失败。

## 结论与边界

本实验支持以下结论：关系路径扩展可以补齐部分多跳问题的中间证据，并且在当前单跳对照中没有降低证据召回。

本实验不能证明：

- 对所有医疗器械问题均有效；
- 已提升最终大模型回答准确率；
- 已具备大规模图谱抽取、社区发现或全局摘要能力；
- 可以取代现有 RAGFlow 混合检索。

如果后续要上线，应先从真实文档自动抽取实体与关系，在未参与建图的新多跳题上复测，再把图路径检索作为低置信度查询的可选补充，而不是直接替换当前稳定检索链路。
