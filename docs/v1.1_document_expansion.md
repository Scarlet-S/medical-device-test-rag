# v1.1 分层文档扩充与入库说明

## 目标

在不改写 v1.0 评测历史的前提下，将知识库从“五份中国监管文件”扩展为三个彼此可区分的知识层：

1. 中国官方监管资料：回答中国注册、质量体系和现场检查问题时的首要依据。
2. FDA 国际对照资料：补充国际监管视角和工程控制思路，不替代中国要求。
3. 项目原创测试实践：把原则转化为可执行的测试设计、证据和退出标准，不宣称为法规要求。

## 新增中国官方资料

| 文档ID | 文档 | 主要补充范围 |
|---|---|---|
| DOC006 | 医疗器械可用性工程注册审查指导原则（2024） | 用户界面、使用错误、关键任务、形成性和总结性可用性评价 |
| DOC007 | 移动医疗器械注册审查指导原则（2025年修订版） | 移动终端、显示限制、网络环境、运行环境和移动应用风险 |
| DOC008 | 医疗器械产品技术要求编写指导原则（2022） | 可验证性能指标、检验方法和产品技术要求编写规则 |

三份文件均为中文资料，并来自国家药监局或国家药监局器审体系的官方附件。

## 新增 FDA 对照资料

| 文档ID | 文档 | 主要补充范围 |
|---|---|---|
| DOC009 | Content of Premarket Submissions for Device Software Functions（2023） | 软件文档级别、需求设计、验证确认、版本历史和未解决异常 |
| DOC010 | Cybersecurity in Medical Devices（2026） | 安全设计、威胁建模、网络安全测试、SBOM、漏洞和补丁管理 |
| DOC011 | Off-The-Shelf Software Use in Medical Devices（2023） | OTS软件风险、验证确认、缺陷、版本配置、维护和停止支持 |

这些文件均为 FDA Final Guidance，仅用于美国监管语境或国际比较。回答中国适用性问题时不得将其内容表述为 NMPA 强制要求。

## 项目原创测试实践

`data/practice_documents` 收录八份项目原创 Markdown：

- 测试策略与生命周期策划
- 基于风险的测试设计与可追溯性
- 权限控制与审计日志测试
- 异常注入、故障恢复与数据完整性测试
- 安装、升级、回滚与兼容性测试
- 性能、并发、稳定性与资源测试
- 变更影响分析与回归测试
- 缺陷管理与测试证据归档

原创实践文件只提供工程方法。涉及监管结论时，必须回到相应官方文件核验。

## 入库顺序

为便于隔离解析问题和检索变化，按以下顺序逐份上传：

1. DOC006
2. DOC007
3. DOC008
4. PRACTICE001-PRACTICE008
5. DOC009
6. DOC010
7. DOC011

先完成中国层和实践层，再加入英文 FDA 层，可以及时判断英文长文档是否挤压中文监管资料的严格 Top-1。

## 单份文档验收

每上传一份文档后：

1. 等待解析完成。
2. 检查标题、目录、正文、表格和附录是否出现空切片、乱码或超长切片。
3. 用两个原文关键词问题和两个自然语言问题进行检索测试。
4. 确认正确切片进入 Top-3。
5. 记录切片数、异常和人工处理。
6. 验收通过后再上传下一份。

## 最低测试问题

### DOC006

- 可用性工程中的关键任务和使用错误如何识别？
- 形成性评价与总结性评价的目的和输出有什么区别？
- 用户界面确认需要保留哪些研究资料？

### DOC007

- 移动医疗器械需要考虑哪些运行环境和终端限制？
- 移动应用的软件更新和网络安全风险如何控制？
- 移动终端兼容性测试应覆盖哪些因素？

### DOC008

- 产品技术要求中的性能指标和检验方法应如何对应？
- 哪些内容适合写入产品技术要求，哪些属于评价性资料？
- 检验方法应具备哪些可操作性和可重复性特征？

### 项目实践层

- 每份实践文档至少设计 3 道场景题。
- 场景题应要求给出测试输入、步骤、预期结果和证据，而不是只复述监管条款。

### FDA 层

- DOC009-DOC011 每份至少设计 6 道独立问题。
- 中文问题与英文原文关键词问题均需覆盖。
- 对中国适用性提问时，正确答案必须明确“FDA对照资料，不是中国监管依据”。

## 回归与发布标准

1. 新题集在正式批量运行前冻结。
2. 同时运行原 50 题开发集、原 30 题留出集和 v1.1 新题集。
3. 旧题回归结果与新题结果分开报告。
4. 原 80 题严格 Top-3 不应出现明显退化；若下降，逐题分析是否由新增近义文件竞争造成。
5. 新增题集调用成功率应达到 100%，并形成可复现 JSON、CSV 和评审记录。
6. v1.1 完成前不覆盖 v1.0 Release 和冻结结果。
